You own integration at /home/nox/Projects/mettle/mistplot. Every lane's code
exists and is green in isolation; your job is the cross-lane proof that they
compose, plus the runnable examples and the golden file.

## Files you may create (nothing else)

- `src/integration_test.mettle`     spec -> scene -> SVG composed in one test
- `cmd/line_svg/main.mettle`        builds data, writes `build/line.svg`
- `cmd/bar_ascii/main.mettle`       one spec rendered to the terminal backend
- `cmd/export_svg/main.mettle`      export path + a second spec in one binary
- `tools/smoke.sh`               build+run examples, cmp goldens, print PASS/FAIL
- `tests/golden/line.svg`        generated by the example, then committed
- `reports/integration.md`       your report

Never edit `src/**`, `docs/`, `notes/`, `tools/check.sh`,
`src/harness.mettle`, or another lane's test. If a library file is wrong,
report it with a minimal repro — do not patch around it in the example.

## What integration must prove

1. One `MpChartSpec` (line, 2 series, 13 points, title with an `&` and a `<`)
   renders: scene node counts > 0, coordinates finite, SVG well-formed enough
   to parse with `grep`-level checks (balanced `<svg>`, no `NaN`, escaped
   entities, `viewBox` matches width/height).
2. The same spec renders twice byte-identically (determinism), and the compiled
   release binary produces the same bytes as debug.
3. `mp_chart_figure` output contains exactly one `<figure`, one `<svg`, and the
   escaped title; the fragment never contains `<script>` even when the title
   does.
4. The terminal backend consumes the same scene (the bar example) and its
   output has exactly `rows` lines of `cols` visible cells.
5. `tools/smoke.sh` exits 0 with: build debug, build release, run both, `cmp`
   the two SVGs against each other and against the golden, run the ASCII
   example and check line count. It must be usable from a clean tree
   (`build/` created if missing) and print one `ok`/`FAIL` line per check with
   the exact command on failure.

## Golden policy

Generate `tests/golden/line.svg` from the debug build, inspect it by eye (it
must look like a chart: axis labels, 2 polylines, legend, title), then commit
it. The golden is the only hand-accepted artifact; never regenerate it to hide
a diff. If a lane change legitimately alters the SVG, say so in your report
and in `reports/director.md`'s next-cycle note.

`build/linux/{debug,release}/<name>`. `tools/smoke.sh` must call mbuild (or those
binaries), never the raw compiler, and it must not need `METTLE` itself.

Both green; paste the exact final lines. `@test` in `t_integration.mettle` must
return nonzero when `mp_fails != 0`, and the file must stay pure enough for the
interpreter (no `fopen`): file output only in `cmd/`.

## Report

the golden SVG, the node counts per chart kind, debug/release `cmp` result, and
every cross-lane mismatch you found (with the file and line) rather than fixed
