# Public API

## `integrations/meodb/mp_meo.mettle`

integrations/meodb/mp_meo — MistPlot live charts driven by MeoDB's committed-change feed: the chart knows WHAT changed (which table, which keys, INSERT or REPLACE) and WHEN (commit_seq and commit time), and it reacts only to data whose transaction committed durably.

Dependencies: meodb/src/feed/feed (MeoFeed, MeoFeedCursor, MeoChange, meo_feed_read, meo_feed_cursor_end, MEO_CHANGE_*), meodb/src/pager/pager (meo_peek_commit_seq), meodb/src/error/status (MEO_* codes), mistplot/live/stream (MpLive, mp_live_seq, mp_live_touch), mistplot/core/buf (MP_* codes), std/mem, std/thread (spin_lock), std/conv (str_from_bytes). The core library under src/ never imports this file, so it builds without MeoDB on disk.

Reload model: MeoDB maps key -> rowid and has no row payloads, so an event cannot carry a value to plot and MistPlot does not decode values from events. A watched table is bound to an MpLive and an app-supplied reload callback; when the table had at least one committed change in a poll (or the feed reported a GAP), mp_meo_poll calls that callback ONCE (coalesced), and the app re-queries the table and refreshes the MpLive. Apps that want incremental handling also register a per-change callback (mp_meo_watch_changes), which sees every event of that table, in commit order, before the coalesced reload.

Poll semantics (mp_meo_poll): * Bounded: the poll drains events up to the feed's newest event at the moment the poll starts (a cursor_end snapshot), in batches of MP_MEO_BATCH with a fixed MP_MEO_KEYBUF key buffer, so a writer that commits continuously cannot keep one poll running forever. * Per event: GAP marks every watched table for reload; an event of an unwatched table only updates the watch-wide "last commit" and the `ignored` counter; an event of a watched table bumps its change counters, records its commit_seq / time_us and calls its change callback. * Then each marked table's reload callback runs once, with the table's `last_reason` set (CHANGES, GAP or INITIAL). A table watched since the previous poll is reloaded once with reason INITIAL, so a chart is loaded before it starts following changes, with no window for a missed commit. * mp_live_touch policy: after a reload callback returns MP_OK, if the MpLive's seq did not move (the callback found identical data, or only edited the template), mp_meo_poll calls mp_live_touch. So the seq always advances after a successful reload: the frame re-renders (its "updated" subtitle refreshes) and web clients polling by ETag get a new frame. * A reload callback that returns non-MP_OK leaves the table marked: it is retried on the next poll. The code is kept in the table's last_error. * Returns the number of tables successfully reloaded, or -MP_ERR_STATE when the feed refused the read (the raw negative MEO code is in the watch-wide stats' feed_error), -MP_ERR_ARG for a null watch.

Threads and locking: * A watch is polled by ONE thread at a time (a UI frame, e.g. MythicUI pass 0, or a producer thread). The MeoDB writer may run on any other thread: meo_feed_read takes only the feed's spin lock for the copy. * The callbacks run on the polling thread and touch the MpLive. The MpLive is not thread-safe, so when another thread renders it (RaizeWeb workers through MpRaizeLive, or a render thread), every callback must run under the SAME lock the renderer uses. mp_meo_poll_locked(w, lock) takes a std/thread spin lock around each callback invocation and the touch (not around the feed read): pass &rl->lock of an MpRaizeLive. A single-threaded MythicUI app polls with plain mp_meo_poll. * A reload that re-queries MeoDB must not use the writer's pager concurrently with the writer (the pager is not thread-safe). Run reads on the writer's thread, or serialize them with the writer under an app "db lock" (as examples/meo_live_chart.mettle does).

"When": per table MpMeoTableStats (mp_meo_table_stats) and watch-wide MpMeoWatchStats (mp_meo_watch_stats). Times are the feed's commit times (CLOCK_REALTIME microseconds, nondecreasing). A GAP caused by this reader falling behind the ring carries time_us 0 in MeoDB, so such a GAP updates commit_seq but not the time. mp_meo_fmt_updated / mp_meo_fmt_subtitle turn them into "hh:mm:ss" (UTC) and "updated hh:mm:ss · commit N" with integer arithmetic only (no float interpolation).

Cross-process (MpMeoProbe): a feed is in-process. When the writer is another process, mp_meo_probe_check reads the persisted commit_seq from page 0 with meo_peek_commit_seq and answers 1 when it moved (reload now), 0 when not.

Ownership: mp_meo_watch_new allocates the watch, its change batch and key buffer; mp_meo_watch_free is the only free path. The MeoFeed, every MpLive and every ctx are BORROWED: free the watch before the feed, and unwatch (or free the watch) before freeing an MpLive. mp_meo_probe_new copies the path; mp_meo_probe_free releases it.

Never prints, keeps no globals.

_Legacy module: its comments predate the doc rules._

## `integrations/mythic/mp_mythic.mettle`

integrations/mythic/mp_mythic — MistPlot charts inside MythicUI.

A scene painter (every MpNode -> MythicUI paint calls inside a layout rect, clipped to it, scene coords 1:1 with logical px), MythicUI's real text measurement installed through mp_text_set_measure while a chart renders, and two widget entry points that cache the rendered scene in a caller-owned MpMythicChart: a static spec (mp_mythic_chart) and a live MpLive (mp_mythic_live).

Semantics follow backends/web/svg: fill is skipped when fill.a == 0, stroke when stroke_w <= 0, node opacity multiplies the alpha, a TEXT node's y is the top of its box and its baseline sits at y + size * 0.8, align start / center / end is relative to x. MythicUI strokes are inside strokes, so a RECT stroke is drawn on the rect grown by stroke_w / 2 (centred, like SVG).

Naming follows MythicUI: callbacks are mp_mythic_*_cb and every export is mp_mythic_ / MpMythic / MP_MYTHIC_.

Geometry: hover reads the frame's MpChartInfo (plot rect, final scales, resolved domains, effective label formats) — mp_mythic_render_info for the static widget, mp_live_info / mp_live_view for the live one — so nothing here re-derives chart/resolve's domain rules or reads MpLive internals.

Measurement: every render saves core/text's current measurer (mp_text_measure_fn / _ctx), installs MythicUI's, and restores the saved one afterwards, so an app's own measurer survives a MythicUI chart.

Lifetimes: the paint callbacks run after the frame callback's passes, so the widget copies the caller's MpChartSpec into the state object. The spec's series arrays and strings stay borrowed and must be alive until the end of the frame in which mp_mythic_chart was called.

_Legacy module: its comments predate the doc rules._

## `integrations/raize/mp_raize.mettle`

integrations/raize/mp_raize — MistPlot charts served by RaizeWeb handlers.

Dependencies: raize_core/context/context (RzContext, RzResponse, rz_ctx_*, rz_req_header, rz_resp_header_set), raize_core/template/vars (RzVarMap), raize_realtime/channel/channel (RzChanRouter, RzChanCtx, rz_chan_define, rz_chan_reply_json, rz_chan_post_broadcast; the hub only through it), mistplot/backends/web/{page,live}, mistplot/live/stream, mistplot/core/buf, std/mem, std/thread (spin_lock). The core library under src/ never imports this file, so it builds without RaizeWeb on disk.

Handler contract: a RaizeWeb handler must RETURN the HTTP status it built (100..599), or the router turns it into a 500. Every mp_raize_* handler helper returns that status, so a handler is one line:

fn h_chart(ctx: RzContext*) -> int32 { return mp_raize_svg(ctx, g_spec, g_opts); }

Ownership: * The spec, its series, and the render options are borrowed for the call. * Each handler helper renders into one scratch MpBuf, which is freed on return; the response copies the bytes into its own body. * Header values are built in stack buffers; rz_resp_header_set copies them into the request arena, so nothing here outlives the call. * The template helpers (mp_raize_tpl_*) render into a CALLER-owned MpBuf and store a view of its bytes in the RzVarMap. That buffer must stay alive and unmodified until rz_template_render_into has returned; the raw substitution copies the bytes into the response body, so the buffer may be freed right after.

Caching policy for static charts: the SVG is rendered on every request (a chart over changing data is the common case) and given a strong ETag that is a 64-bit FNV-1a hash of the bytes, "mp-<16 hex>", with `Cache-Control: no-cache` (store, but revalidate). A matching If-None-Match answers 304 with no body, which saves the transfer, not the render. A caller that knows its chart is immutable overrides Cache-Control afterwards with rz_resp_header_set(ctx->resp, "Cache-Control", "max-age=3600").

Failure: a render error answers 500 with the short text body "chart render failed\n" (the MP_* code is not leaked to the client); a null ctx/resp returns 500 without touching anything.

Never prints. The one global is the channel registry (see "Push over RaizeWeb channels"). The one extern is clock_gettime, read once per mp_raize_live_new for the live ETag generation.

## `src/backends/terminal/ascii.mettle`

`import "mistplot/backends/terminal/ascii";`

backends/terminal/ascii — the terminal backend: one character cell per (col,row) of a cols x rows grid, emitted as ANSI SGR text or as plain text.

Dependencies: renderer/scene, renderer/backend, core/{buf,color} and std/math (floor). Nothing chart-shaped is imported: the backend walks the display list and does no arithmetic beyond the coordinate mapping and the text baseline shift.

Ownership: mp_ascii_render clears `out` and writes only into it. The cell grid is a stack array of MP_ASCII_MAX_CELLS (200*80) cells, so the only allocation is `out`'s growth and there is nothing to free.

Determinism: the bytes are a pure function of the scene, the two viewport numbers, the grid size, the theme and the sign of o->pad. No ids, no time, no addresses, no locale — two renders of one scene are byte-identical.

Interpretation: * canvas: mp_ascii_render uses cols = (int32)o->width, rows = (int32)o->height, truncated; mp_ascii_render_grid takes cols and rows and maps the o->width x o->height scene onto them (lay the chart out at mp_ascii_chart_width/height for text to fit one line per row). A non-finite, non-positive or > 200x80 size is MP_ERR_ARG (after clear); * mapping: col = floor(x / o->width * cols), row = floor(y / o->height * rows) — the divisor is the float viewport, not the truncated cell count; a mapped cell is clamped to ±4096 so a wild coordinate cannot spin the rasterizer; * RECT: the half-open cell range [col(x), col(x+w)) x [row(y), row(y+h)) is filled with the fill colour as a background SGR and its glyphs are cleared to spaces (painter's order: a later opaque rect covers earlier glyphs). fill.a == 0 skips the node; a rect thinner than one cell vanishes. Rects are fills only — stroke is ignored; * LINE/POLY: Bresenham per segment; the glyph of a cell is the direction of the step leaving it (`-` horizontal, `|` vertical, `\` when x and y move the same way, `/` when they move oppositely) and the last cell keeps the incoming direction. A cell that already holds a different glyph becomes `+`, which is where junctions and crossings come from. No anti-aliasing; * CIRCLE: midpoint outline of `o`; `@` when the radius is < 1.5 cells. The radius is measured in columns (r / width * cols) because a cell is not square and the aspect ratio is not corrected; * TEXT: one cell per byte, clipped per cell to the canvas. The glyph row is the row containing the baseline y + size*0.8 (the same baseline choice backends/web/svg documents), or on the grid path the box middle y + size*0.6; a later text overwrites an earlier one cell by cell. The column is the anchor, shifted left by len/2 for CENTER and by len for END. Text is ASCII-only: bytes 0x20..0x7E are drawn as themselves and every other byte (control or >= 0x80, i.e. every UTF-8 continuation byte) becomes `?`; * ANSI: `ESC[38;2;r;g;bm` foreground, `ESC[48;2;r;g;bm` background, and `ESC[0m` at the end of every row (the last row's reset is the document's final reset). SGR is emitted only when a cell's colour differs from the row's current colour, and never for a space's foreground, so a blank canvas carries no colour escapes. o->theme.fg is the default foreground; * plain mode (o->pad < 0) emits no escapes at all and trims trailing spaces from each row. Every row ends with a newline in both modes.

## `src/backends/web/live.mettle`

`import "mistplot/backends/web/live";`

backends/web/live — live charts on the web: the SVG of an MpLive's current frame, and the browser snippet that polls for it.

Dependencies: live/stream + renderer/{scene,backend} + core/buf + backends/web/svg. This file and page.mettle are the only web modules that may import above the renderer.

Ownership: every entry point clears `out` and writes only into it; nothing is allocated here. mp_live_svg updates the MpLive (which owns its scenes) and serializes the cached scene; the MpLive itself stays the caller's.

Server renders, browser swaps: mp_live_embed writes <div class="mp-live" data-src="URL" data-interval="N"></div> <script>...</script> and the script reads both values back from its *own* preceding element (document.currentScript.previousElementSibling), so several embeds on one page never share state and the page needs no ids. mp_live_embed_with puts an initial SVG inside the div so the first paint is not blank. That SVG is inserted RAW (not escaped): it must be MistPlot output (mp_live_svg / mp_svg_render), never caller-supplied markup. The script text is one constant: the URL is never interpolated into JavaScript, only written once as an HTML-escaped attribute value (& < > " ' become entities, so a URL can neither close the attribute nor open a tag). Polling sends If-None-Match with the last ETag it saw, swaps the div's innerHTML on 200, does nothing on 304, and doubles its delay on an error, going back to the interval after the next success. Rules the script keeps: * the ETag is remembered only after the body arrived and was swapped in, so a failed body read never leaves the client claiming a frame it does not show (it would then get 304s for it forever); * the error delay is min(2 * delay, 32 * interval, 60000 ms) but never below the interval: setTimeout treats a delay above 2^31-1 ms as 0, so an unbounded backoff over a long interval would become a tight loop; * polling stops once the div is no longer in the document (isConnected), so a page that replaced the embed does not keep a timer per old copy. interval_ms is limited to 1..MP_LIVE_MAX_INTERVAL_MS (one hour) by the server side; the script clamps it the same way.

Push: mp_live_embed_ws adds data-ws and data-topic (escaped the same way) and a longer script that joins the topic over a Phoenix v2 socket (`?vsn=2.0.0`, frames [join_ref, ref, topic, event, payload], a heartbeat on topic "phoenix" every 30 s). The server sends no frames over it, only tags: the join reply's response and each "frame" event carry {"tag": "<t>"}, where `"<t>"` (quoted) is the live endpoint's current ETag. When that differs from the ETag of the frame on screen, the script fetches `url` with If-None-Match exactly as a poll does. Extra rules: * one fetch in flight at a time; a tag that arrives during a fetch is remembered and fetched after it if the new frame does not already carry it; * while the socket is not joined (connecting, refused, closed, errored) the polling loop runs with the same backoff; a successful join stops it, and a failed fetch while joined is retried after the backoff delay; * reconnects back off from 1 s to 30 s; a removed div closes the socket and clears every timer.

This is the only MistPlot output that contains <script>; svg.mettle and page.mettle stay script-free. Output is deterministic: a pure function of the arguments.

_Legacy module: its comments predate the doc rules._

## `src/backends/web/svg.mettle`

`import "mistplot/backends/web/svg";`

backends/web/svg — turns a scene IR into one deterministic SVG document.

Dependencies: renderer/scene, renderer/backend and core/{buf,color,format} only — no float classification from std/math is needed because a NaN is its own witness (`v != v`) and the only other rejection is an absolute-magnitude clamp. Nothing chart-shaped is imported: the backend walks the display list and does no arithmetic beyond the text baseline shift.

Ownership: mp_svg_render clears `out` and writes only into it; the only allocation is `out`'s growth. A growth failure returns MP_ERR_ALLOC with a partial document left in `out`.

Determinism: the bytes are a pure function of the scene and the two viewport numbers — no ids, no timestamps, no random values, no allocation addresses, no `system()`-derived anything. Two renders of one scene are byte-identical, which is what the golden file and the debug/release diff depend on.

Serialization policy: * exactly one root at depth 0, every node on its own line at depth 1 (two spaces of indent), trailing newline, no XML declaration; * attribute order is fixed and global: geometry (x y width height, or cx cy r, or x1 y1 x2 y2, or points, or x y), paint (fill stroke stroke-width), then opacity, then text metrics (font-family font-size text-anchor), then class; * numbers: at most 3 decimals with trailing zeros and a trailing dot stripped, `-0` -> `0`, NaN/±inf -> `0`, and |v| >= 1e15 -> `0` so the formatter's scientific fallback can never leak `e+` into the markup; * colors: `#rrggbb` when a == 255, otherwise `rgba(r,g,b,a/255)` with the alpha written at exactly three decimals (core/color keeps the literal 0..255 spelling for its callers); * `stroke` is omitted when `stroke_w <= 0` and `opacity` when it is exactly 1.0. A fill with alpha 0 is written as `fill="none"` on the shapes SVG fills by default — rect, circle and polyline, whose initial fill is BLACK (an open polyline fills its implied polygon, which would turn every line chart into a black blob in browsers). A `line` has no interior, and a text node with alpha 0 is never emitted by the chart layer, so both still omit it; * text is escaped (& < > " '), carries font-family="system-ui, sans-serif", font-size and text-anchor, and its y is node.y + size*0.8 because renderer/scene stores the TOP of the text box, not the baseline; * class is `mp-c-<name>` for the eight base classes and `mp-c-series mp-s-<cls - MP_CLS_SERIES>` for cls >= MP_CLS_SERIES; a cls outside both sets (the chart layer never emits one) becomes `mp-c-<n>` so nothing is silently renamed; * o->theme and o->pad are not consumed: colors are already baked into the nodes by chart/resolve, and padding is a layout concept. o->aria is not consumed either, because the output carries no ids (no aria-labelledby is possible); the root always carries role="img".

## `src/chart/layout.mettle`

`import "mistplot/chart/layout";`

chart/layout — the frame rectangles of one chart, with margins derived from measured text.

Dependencies: core/{geom,text,scale,data} + chart/spec. No scene, no backend, no allocation: layout only measures strings it is handed.

Auto margins, with th = mp_text_height(12) = 14.4: top    = 1.6*th (title) + 1.25*th (subtitle) + 8 + (y title ? th + 4 : 0) left   = widest y tick label + 10 right  = legend_w + 12 when the legend is on the right, else 8 bottom = th + 10 + (x title ? 1.4*th + 4 : 0) + (bottom legend ? 18 + 4 : 0) plus one text guard of its own: the first (and last) x tick label is centred on the plot edge, so each side needs half its measured width, and left/right grow to half the outermost label + 2 when that is wider. The axis-title band is additive to the tick-label band, so the x tick labels *and* the x title fit inside the frame and nothing has to be drawn outside the canvas.

The y title is horizontal (MythicUI has no rotated text, and one rule for every backend keeps them identical), so it gets its own band above the plot, left-aligned at the canvas edge, clear of the top y tick label (which is centred on plot.y and reaches th/2 above it). Sharing the left band with the tick labels would put it on top of the middle tick label.

legend_w = widest series name + 24 (swatch 12 + gap 4 + right pad 8).

Clamp rule: when left+right > width-2 (or top+bottom > height-2) both members of the pair are scaled down by the same factor, so the plot keeps a positive extent and still sits inside the canvas: plot.w = 2 for a canvas whose labels would eat it. plot.w/plot.h are floored at 1 for degenerate canvases.

## `src/chart/resolve.mettle`

`import "mistplot/chart/resolve";`

chart/resolve — the one chart entry point: a spec in, a scene out.

Dependencies: chart/{spec,layout,axis} + core/{buf,color,data,format,geom, scale,text,ticks} + renderer/scene. No backend import and no std/io: the library never prints.

Ownership: `out` is the caller's scene; mp_chart_render clears it and writes only into it. Two float64 arrays per line series are allocated and freed before returning. The scene owns its text, so the spec's strings may die as soon as the call returns.

Pipeline: validate -> union extents -> tick *values* from the data domain (pass 1) -> measured layout -> final pixel scales over frame.plot (pass 2) -> emit in painter's order: background, plot, grid, axes, series, legend, title. Empty but valid data is not an error: it renders the background and the title and returns MP_OK.

Fixed domains: an axis with `*_fixed` set uses exactly [*_min, *_max] in place of the data extent, for the ticks, the layout and the scales; neither the zero baseline nor the degenerate-span fix touches it (a fixed axis with non-finite bounds or max <= min is MP_ERR_ARG). Marks outside a fixed domain follow one backend-neutral rule: line points are clamped to the plot rect on both axes, scatter points outside are skipped, and bars whose value is outside the fixed y domain are skipped (the bars that remain are clipped vertically to the plot rect, because their zero baseline may lie outside it). A bar chart's x axis is a band axis, so `x_fixed` is ignored there. With no fixed axis no mark is clamped or skipped.

Nice domains: a linear value axis whose domain is NOT fixed is extended outward to the nearest tick of its own step (core/ticks mp_ticks_nice), so the top and bottom ticks sit on the plot edges and are labelled, and the tallest bar or highest point does not touch the plot top. This applies to the y axis of every chart kind. The x axis of line/scatter charts keeps its data extent (a time series should start and end at the plot edges; a live window is a fixed domain anyway).

Time axes: an axis whose label format is MP_FMT_TIME takes its tick step from clock-shaped candidates (mp_tick_step_time: 0.1 s .. 12 h). When that step is below one second the axis labels switch to MP_FMT_TIME_TENTHS, so adjacent labels never repeat (x = [0, 2] reads 00:00.0 00:00.5 ...). The resolved formats are reported in MpChartInfo.

Geometry out (mp_chart_render_info): the plot rect, both final scales, the resolved domains, the band count and the effective label formats of the frame just rendered, so a host (hover, hit testing) never re-derives resolve's domain rules. `valid` is false when nothing was laid out (an error or empty data).

## `src/core/buf.mettle`

`import "mistplot/core/buf";`

The growable byte buffer that holds every emitted string (scene text, SVG, terminal output, export payloads). Uses core/error, core/mem (counted), core/color and core/format. ## `src/live/decimate.mettle`

`import "mistplot/live/decimate";`

live/decimate — min/max decimation of a ring into caller columns, so a frame costs O(plot width) points no matter how many samples the ring holds.

Dependencies: live/ring + std/math. No allocation: the output columns and their capacity are the caller's (live/stream sizes them to 4 * plot width), and the per-bucket bookkeeping lives in out_xs itself (see below).

mp_decimate_minmax(r, x0, x1, buckets, out_xs, out_ys, cap) -> n: * only samples with finite x and y inside [x0, x1] (inclusive) take part; * when at most `cap` samples take part they are copied as they are, oldest first, and n is their count; * otherwise [x0, x1] is split into `b` equal buckets, where b = buckets lowered to cap / 4 so every bucket's four points fit (and at least 1). A sample's bucket is computed from its x alone, so ring order does not matter: one pass records, per bucket, the ring positions of its first, min-y, max-y and last sample; a second pass emits the buckets in x order, each bucket's distinct samples sorted by (x, ring position). Peaks therefore survive whatever the push order: the extremes of every bucket are drawn, n <= 4 * b <= cap, and no sample is dropped for lack of room; * nothing is ever written at or past out[cap]; when cap < 4 the single bucket's points are truncated to the first `cap` of them.

Sorted input (nondecreasing x, the normal case): every bucket is one contiguous run of the ring, so the output is exactly what a single in-order pass would emit — first, min, max, last of each run in ring order.

Scratch: the bookkeeping pass stores bucket k's four ring positions (as float64, exact for any ring <= MP_MAX_COUNT) in out_xs[4k .. 4k+3], -1 for an empty bucket. The emit pass reads bucket k's four positions into locals before writing any output, and bucket k's output starts at an index <= 4k (each earlier bucket emitted at most four points), so a write only ever lands on bookkeeping that has already been read.

_Legacy module: its comments predate the doc rules._

## `src/live/stream.mettle`

`import "mistplot/live/stream";`

live/stream — MpLive, the realtime chart object: rings in, a cached scene out, rebuilt only when something changed.

Dependencies: live/{ring,decimate} + chart/{spec,resolve} + renderer/scene + core/{buf,data,color} + std/mem, std/math, std/conv. No backend import: web and MythicUI read the cached scene through mp_live_scene.

Ownership: mp_live_new returns an MpLive owned by the caller; mp_live_free releases, in one path, the rings, the series-name copies, the view array, the two scratch columns and both scenes. Everything else is borrowed: * mp_live_spec returns a pointer into the MpLive (the template). Its strings (title, labels) are borrowed from the caller exactly like any MpChartSpec's; its `series` / `n_series` are ignored, because every frame renders a copy that points at the MpLive's own views; * the views are MpSeries *borrowed* over the scratch columns and the name copies. They are never passed to mp_series_free; * mp_live_scene returns the cached scene, valid until the next update; * mp_live_info returns the MpChartInfo of that same frame (a pointer into the MpLive, updated only by a successful update); * mp_live_view(lv, i) returns series i's view (borrowed, rebuilt by every update attempt) for hosts that look up the samples the frame drew.

Change tracking: `seq` (int64) starts at 0 and grows by one on every push, series rename, window change, mp_live_clear and mp_live_touch (call that after editing the template). `generation` is an opaque 64-bit value the caller may set (mp_live_set_generation, e.g. the process start time) so that "generation-seq" identifies a frame across process restarts, where seq alone starts again at 0; MistPlot never interprets it. `built_seq` is the seq the cached scene was built from; dirty is "no frame yet, or seq moved". mp_live_update renders into a back scene and swaps it in only on success, so a failed render keeps the last good frame, leaves the object dirty and records the code for mp_live_error.

Window: span > 0 shows [x0, latest_x], where latest_x is the largest finite x pushed to any series and x0 = latest_x - span clamped up to the earliest retained sample. So at startup, while the data covers less than the span, the axis starts at the first sample (no negative times) and widens until it is `span` wide, then slides at that fixed width. When every retained sample has the same x the window is [latest_x, latest_x + span]. The per-frame spec copy gets x_fixed = true with that range (the caller's template is never modified), so the x axis slides with the data instead of jumping with the extent. Each series also draws its last sample before x0 (if any), which the line rule clamps onto the left edge, so the line reaches the plot's left side. A window that cannot be represented — x0 or the span not finite, or latest_x - span rounding to latest_x (epoch nanoseconds with a span of seconds) — does not fail the frame: that frame falls back to the span == 0 rule below. span == 0 shows everything: the decimation range is the template's fixed x domain when it has one, else the union of the rings' extents.

Decimation: each series is decimated (live/decimate) into its own slice of two scratch columns sized 4 * ceil(width) per series (width clamped to [1, MP_LIVE_MAX_COLUMNS]), with ceil(width) buckets and an output cap of 4 * ceil(width) for *this* frame's width. The scratch grows when the template's width grows and is never shrunk (a cap from the scratch size would stop decimating after the chart was once wider).

Threads: an MpLive is not thread-safe by itself. A producer that pushes and a renderer that updates must share it under the application's lock.

## `src/scene/path.mettle`

`import "mistplot/scene/path";`

Walks line, polyline and path nodes as a flat run of move/line points, flattening cubic segments adaptively, and turns a dash style into a dash pattern. Depends on scene/scene and std/math. The iterator borrows the scene's arrays: do not add to the scene while iterating. Allocates nothing.

### `mp_path_iter`

```mettle
fn mp_path_iter(s: MpScene*, nd: MpNode*, it: MpPathIter*, tol_px: float64) -> int32
```

Starts iterating the points of a line, polyline or path node. Lines and polylines yield one MP_PATH_MOVE then MP_PATH_LINE per further point. Paths yield their moves and lines; a close yields a line back to the subpath start (when not already there); a cubic yields clamp(ceil(L / tol_px), 1, 32) lines, where L is the length of its control polygon (an upper bound on the curve length).

| `it` | `MpPathIter*` | The iterator to initialise. Valid: non-zero. |
| `tol_px` | `float64` | Flattening tolerance. Units: px. Valid: > 0; anything else uses 0.5. |

**Returns:** MP_OK, or an error code.

**Errors:**

- `MP_ERR_ARG` s, nd or it is 0, or nd is another kind; it then yields nothing.

**Memory:** it borrows the scene's arrays until the next add, clear or free of s.

**Threads:** One thread at a time per scene.

**Cost:** O(1).

## `src/scene/scene.mettle`

`import "mistplot/scene/scene";`

The backend contract: a flat display list of primitives in painter's order, owned by the scene. Text bytes, points (x,y pairs) and path command bytes live in three scene arrays and nodes refer to them by int32 offset, so a scene outlives whatever built it. Depends on core/error, mem, buf, color and geom. Capacities only grow: clearing keeps them, so rebuilding a scene of the same size allocates nothing. A polyline or path is built in place between *_begin and *_end; while one is open every other add returns MP_ERR_STATE. Node and point pointers are borrowed and any add may move them.

## `src/data/col.mettle` (internals)

`import "mistplot/data/col";`

MpCol, the sample storage behind one series: a ring of (x, y) pairs that grows while keep == 0 and overwrites its oldest sample once it holds keep > 0 samples. Uses core/error and core/mem; storage is allocated at the first push and grows geometrically (up to keep), so a full ring pushes without allocating. Samples are stored as given, non-finite ones included. `sorted` says whether the finite x values have been nondecreasing since the last clear; `gen` and `pushes` let a cache built from the column (data/summary) notice every change.

### `MpCol`

```mettle
struct MpCol
```

A column of samples; initialise with mp_col_init and release with mp_col_free. Read the fields through the mp_col_* functions; data/summary also reads gen and pushes.

| Field | Type | Description |
|---|---|---|
| `xs` | `float64*` | x storage, cap slots; 0 before the first push |
| `ys` | `float64*` | y storage, cap slots |
| `cap` | `int64` | allocated slots |
| `head` | `int64` | slot of the oldest sample |
| `n` | `int64` | samples held |
| `keep` | `int64` | ring size; 0 = unbounded |
| `sorted` | `bool` | finite x nondecreasing since the last clear |
| `has_last` | `bool` | a sample with finite x was pushed since the last clear |
| `last_x` | `float64` | x of the newest push with a finite x (valid when has_last) |
| `gen` | `int64` | bumped by every change other than a push (clear, keep, set) |
| `pushes` | `int64` | pushes since mp_col_init; never decreases |

**Memory:** Owns xs and ys (allocated through core/mem); the struct itself belongs to its container (usually embedded in a series).

`import "mistplot/data/decimate";`

Min/max decimation of a column into caller arrays: the O(n) path for columns that are unsorted or too small for data/summary. Uses data/col and core/error; allocates nothing (bucket bookkeeping lives in the output x array). Only samples with finite x and y inside the range take part. Buckets come from x alone, so push order never decides which samples survive: each bucket emits its first, min-y, max-y and last sample, sorted by (x, position), and the extremes of every bucket are always drawn.

### `mp_col_decimate`

```mettle
fn mp_col_decimate(
  col: MpCol*,
  x0: float64,
  x1: float64,
  cols: int32,
  lead: bool,
  xs: float64*,
  ys: float64*,
  cap: int64
) -> int64
```

Decimates the samples of col inside [x0, x1] into at most cap points. When at most cap samples take part they are copied as they are, oldest first. Otherwise [x0, x1] is split into b equal buckets (b = cols, lowered to cap / 4 and at least 1) and each bucket emits its distinct first, min-y, max-y and last samples, buckets in x order. With lead, the range starts instead at the largest finite x below x0 that has a finite y, so a line can enter the plot from its left edge.

| Parameter | Type | Meaning |
|---|---|---|
| `col` | `MpCol*` | The column. Valid: non-zero. |
| `x0` | `float64` | Range start (inclusive). Units: data units. Valid: finite; otherwise 0 is returned. |
| `x1` | `float64` | Range end (inclusive). Units: data units. Valid: finite and >= x0; otherwise 0 is returned. |
| `cols` | `int32` | Bucket count before the cap lowers it. Units: columns. Valid: >= 1. |
| `lead` | `bool` | Whether to include the last sample before x0. |
| `xs` | `float64*` | Output x. Valid: non-zero with room for cap values. |
| `ys` | `float64*` | Output y. Valid: non-zero with room for cap values. |
| `cap` | `int64` | Output capacity. Units: points. Valid: >= 1; below 4 the single bucket is truncated to cap points. |

**Returns:** Points written (0 .. cap), or -MP_ERR_ARG.

**Errors:**

- `MP_ERR_ARG` col, xs or ys is 0, cols < 1 or cap < 1 (returned negated); nothing is written.

**Memory:** Writes only xs[0 .. cap) and ys[0 .. cap); xs also serves as scratch.

**Cost:** O(n), two or three passes; no allocation.

## `src/data/smooth.mettle` (internals)

`import "mistplot/data/smooth";`

Monotone cubic tangents (Steffen's method, as in d3's curveMonotoneX) for smoothing a polyline without overshoot: each Hermite segment between two points stays within the y range of those points. Uses core/error; pure arithmetic, no allocation. Callers split their points into runs of strictly increasing finite x before calling.

### `mp_smooth_slopes`

```mettle
fn mp_smooth_slopes(xs: float64*, ys: float64*, n: int64, out: float64*) -> int32
```

Computes the tangent dy/dx at every point of a run for monotone cubic smoothing. Interior tangents follow Steffen; each end uses its one-sided secant. The cubic for segment i then has control points (x_i + h/3, y_i + m_i h/3) and (x_i+1 - h/3, y_i+1 - m_i+1 h/3), where h = x_i+1 - x_i.

| Parameter | Type | Meaning |
|---|---|---|
| `xs` | `float64*` | Point x. Units: px or data units. Valid: n finite values, strictly increasing. |
| `ys` | `float64*` | Point y. Units: same space as the tangents wanted. Valid: n finite values. |
| `n` | `int64` | Point count. Valid: >= 0; 1 point gets tangent 0. |
| `out` | `float64*` | Receives n tangents. Valid: room for n values; may not alias xs or ys. |

**Returns:** MP_OK, or an error code.

**Errors:**

- `MP_ERR_ARG` a pointer is 0 (with n > 0), n < 0, or the points are not finite with strictly increasing x; out is not written.

**Memory:** Writes only out[0 .. n); nothing is retained.

**Cost:** O(n); no allocation.

## `src/data/summary.mettle` (internals)

`import "mistplot/data/summary";`

MpSummary, the O(width) frame engine for large sorted columns: a ring of min/max buckets on an absolute grid (bucket k covers [k*bw, (k+1)*bw) with bw a power of two, so bucket edges never depend on history). Pushes update it in O(1); a frame merges the visible buckets into pixel columns. Uses data/col, data/decimate (the fallback for unsorted columns) and core/{error,mem}. The ring is allocated once, at the first rebuild; afterwards nothing allocates. Every emitted point is a real sample, and the y extent of the emitted points equals the y extent of the visible samples.

**Constants**

| Name | Type | Value | Description |
|---|---|---|---|
| `MP_SUMMARY_BUCKETS` | `int32` | `2048` | Default buckets per visible domain (the bucket width is a power of two near span / B). |
| `MP_SUMMARY_MIN_LEN` | `int64` | `8192` | Columns shorter than this are cheaper to scan directly than to summarise. |

### `mp_summary_push`

```mettle
fn mp_summary_push(s: MpSummary*, x: float64, y: float64)
```

Feeds one sample that was just pushed to the summarised column. Call it after every push to the column, in the same order, or never: emit replays the newest pushes it has not seen, so skipping only some of them forces a rebuild. An x below the previous finite x invalidates the summary (the column is then unsorted and frames use mp_col_decimate until it is cleared).

| Parameter | Type | Meaning |
|---|---|---|
| `s` | `MpSummary*` | The summary. Valid: any; 0 is ignored. |
| `x` | `float64` | Sample x. Units: data units. Valid: any; non-finite samples are skipped. |
| `y` | `float64` | Sample y. Units: data units. Valid: any; non-finite samples are skipped. |

**Memory:** Nothing is allocated (a full ring drops or merges buckets instead).

**Cost:** O(1) amortized.

### `mp_summary_emit`

```mettle
fn mp_summary_emit(
  s: MpSummary*,
  col: MpCol*,
  x0: float64,
  x1: float64,
  cols: int32,
  lead: bool,
  xs: float64*,
  ys: float64*,
  cap: int64
) -> int64
```

Writes the visible samples of col in [x0, x1], reduced to at most cap points. When the visible samples fit they are copied as they are. Otherwise the summary is synced (or rebuilt from the column) and its buckets are merged into min(cols, MP_SUMMARY_BUCKETS, cap / 4) equal pixel columns; each column emits its distinct first, min-y, max-y and last samples in x order. An unsorted column (or a range the bucket grid cannot represent) falls back to mp_col_decimate. With lead, the last sample before x0 with finite x and y is written first.

| Parameter | Type | Meaning |
|---|---|---|
| `s` | `MpSummary*` | The summary. Valid: an initialised summary. |
| `col` | `MpCol*` | The column it summarises. Valid: non-zero; always the same column. |
| `x0` | `float64` | Visible start (inclusive). Units: data units. Valid: finite; otherwise 0. |
| `x1` | `float64` | Visible end (inclusive). Units: data units. Valid: finite and >= x0; otherwise 0. |
| `cols` | `int32` | Pixel columns. Units: device px. Valid: >= 1; above MP_SUMMARY_BUCKETS it is clamped. |
| `lead` | `bool` | Whether to write the last sample before x0 first. |
| `xs` | `float64*` | Output x, nondecreasing. Valid: non-zero with room for cap values. |
| `ys` | `float64*` | Output y. Valid: non-zero with room for cap values. |
| `cap` | `int64` | Output capacity. Units: points. Valid: >= 1; with fewer than 4 * cols + 1 slots the column count is lowered, and below 5 the output is truncated. |

**Returns:** Points written (0 .. cap), or a negated error code.

**Errors:**

- `MP_ERR_ARG` s, col, xs or ys is 0, cols < 1 or cap < 1; nothing is written.
- `MP_ERR_ALLOC` the bucket ring could not be allocated; the summary stays invalid.

**Memory:** Writes only xs[0 .. cap) and ys[0 .. cap). The first rebuild allocates the ring (about 72 * (2 * nb + 2) bytes); nothing else is allocated, ever.

**Cost:** O(log n + nb + cols) per frame plus O(n / nb) for the two edge buckets; a rebuild (first frame, span change, keep or clear) is O(n).
